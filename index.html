Systems design & how computers work

A lot of new grads can call APIs but not explain what happens underneath. I can — and I design systems with that in mind.

System design

End-to-end architecture for AI pipelines and enterprise apps: ingestion → storage → retrieval → inference → API/UI. Tradeoffs around latency, cost, failure modes, and data consistency (e.g. hybrid RAG retrieval, multi-source BI models).

Memory & execution

Stack vs. heap, pointers, allocation, call stacks, and how program state lives in memory — so debugging and performance issues are not a black box.

Machine-level & assembly

Assembly/C coursework and low-level C projects: registers, instruction fetch–decode–execute, and how high-level code maps to what the CPU actually runs.

Language implementation

Built a bytecode VM (C), a Lox interpreter, and a Lisp interpreter — lexing, parsing, evaluation, and runtime environments. That means I understand parsing, scopes, and what “running code” really means.
